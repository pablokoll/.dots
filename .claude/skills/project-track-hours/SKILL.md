# project-track-hours

## Vault
`/home/pablo/Dropbox/Aplicaciones/remotely-save/personal-vault/`

## Protocol

### 1. Find the Project Index
- Check `.claude/project-link.md` → read `vault_path`
- Derive project folder: parent dir of `vault_path`
- `project_name` from `project-link.md`

### 2. Parse hours from all sources (silent)

**Source A — Tickets** (`<project_folder>/tickets/*.md`):
- Read each ticket file
- Find `## Work Log` section
- Parse every entry matching: `### YYYY-MM-DD` followed by a line or header containing `Xh` or `X.Xh` or `~Xh` or `Xhs`
- Extract: date, hours, ticket ID (from `ticket:` frontmatter), ticket name (from `# ID — Name` heading), summary (first line of description after the date header)
- Also accept format: `### YYYY-MM-DD — Xh` (date and hours on same line)

**Source B — Project Index Work Log** (`<project_folder>/<Index>.md`):
- Find `## 📋 Work Log` section
- Parse entries matching: `### YYYY-MM-DD` or `### YYYY-MM-DD (~Xhs)` or `### YYYY-MM-DD — ~Xhs`
- Extract hours from the header line (look for `~Xh`, `Xhs`, `~X.Xhs` patterns)
- Extract summary from `**Resumen:**` or `**Summary:**` line
- Label source as "General / no ticket"

**Parsing rules:**
- Hours formats to recognize: `2h`, `2.5h`, `~2h`, `~2.5hs`, `(~2hs)`, `— 2h`, `2 horas`
- If no hours found for an Index entry, skip it (don't guess)
- Deduplicate: if a ticket work log entry and an Index entry are clearly the same session (same date, similar summary), prefer the ticket entry
- Group all entries by month (YYYY-MM) and within each month by ISO week (Week N: Mon DD – Sun DD)

### 3. Check for existing hours log

Check if `<project_folder>/hours/YYYY-MM-hours-log.md` exists for the current month:
- **Exists** → read it, regenerate from scratch with fresh data (always overwrite, don't append)
- **Doesn't exist** → create `hours/` folder silently if needed, create new file

### 4. If user passed additional input
If the user said something like "agregá X horas en Y" or "también trabajé Z horas en W", incorporate as a manual entry with today's date and a `[manual]` tag in the description.

### 5. Write the hours log

File: `hours/YYYY-MM-hours-log.md`

```markdown
---
tags:
  - project/hours
project: <project_name>
month: YYYY-MM
generated: YYYY-MM-DD
total_hours: <sum of all hours>
---

# Hours Log — <Month YYYY> — <Project Name>

**Total: <N>h**

---

## Week N — Mon DD – Sun DD MMM

| Date | Ticket | Summary | Hours |
|------|--------|---------|-------|
| YYYY-MM-DD | BLMSHPF-XXXX | Short summary | Xh |
| YYYY-MM-DD | General | Short summary | Xh |

**Week total: Xh**

---

## Week N — ...

...

---

*Generated by /project-track-hours on YYYY-MM-DD*
```

Rules for the table:
- `Ticket` column: ticket ID (e.g. `BLMSHPF-5120`) or `General` for Index entries
- `Summary` column: first sentence of the work log entry, max ~60 chars, truncate with `…` if longer
- Sort rows within each week by date ascending
- Show weeks that have entries only (skip empty weeks)
- Week total at the bottom of each week block
- Grand total at the top under the `# heading`

### 6. If multiple months have data
Run the same process for each month that has entries and generate/update one file per month (`2026-04-hours-log.md`, `2026-05-hours-log.md`, etc.).

Ask the user first: "Found entries across X months (Apr, May, Jun). Generate all or just current month?"

### 7. Confirm
"Hours log updated: `hours/YYYY-MM-hours-log.md` · Total: Xh across N entries."

## Rules
- Always regenerate from scratch — never append to existing hours log (data comes from tickets which are the source of truth)
- Output language follows active session language. Default: English.
- If no hours found anywhere, say so and suggest running `/ticket-log` to log hours first
- Don't modify any ticket files or the Project Index — read only
- `hours/` folder lives inside the vault project folder (same level as `tickets/`, `sessions/`)
